# Parity ledger — sub-project 6c-1

ADK-Go commit: see `docs/parity/ADK_GO_COMMIT`. Test-name rule: see the 1b spec § Parity tooling.

Rows below the table header are generated by `python3 scripts/parity-check --ledger 6c-1 --generate`
from annotations in each Go test file's Rust target. Do not edit rows by hand:
- `fn test_foo` (or `fn example_foo` for a Go `ExampleFoo`) in the target → `ported`; a
  `// parity: adapted: <reason>` line within the 3 lines above the `fn` → `ported (adapted: <reason>)`;
- a line `// parity: skipped TestFoo: <reason>` in the target → `skipped`.

Scope: `gopkg.in/yaml.v3` v3.0.1 (the version ADK-Go's `go.mod` pins), ported to the internal crate
`crates/gadk-goyaml` (`publish = false`; no gadk crate depends on it in 6c-1, and the `gadk`
façade never does): reader, scanner, parser, emitter, writer, tag resolution, the `Node` tree
(`Document`), `Marshal`/`Unmarshal`, `Encoder`/`Decoder`, decode into Go's `interface{}`
(`GoValue`), the alias limits, and a serde `Serializer`/`Deserializer` that follows yaml.v3's
reflection rules (`InlineMap` for Go's `,inline` map). yaml.v3's test files are ledgered as
`yaml.v3/<file>_test.go`; `scripts/parity-check` reads them from the module (`$GOYAML_DIR`, else
`$(go env GOMODCACHE)/gopkg.in/yaml.v3@v3.0.1`), collects their gocheck methods
(`func (s *S) TestXxx(c *C)`) and `Example` functions (not the `Benchmark`s of `limit_test.go`),
and their targets are `crates/gadk-goyaml/src/parity_tests/yaml_v3_<file>.rs`.
`suite_test.go` holds only the gocheck hook `func Test(t *testing.T)` and has no rows.
Table-driven Go tests are ported row by row; a row that relies on a not-applicable feature
(below) is skipped inside the ported test with its reason in a comment, and the test is then
`ported (adapted: …)`. The crate's own tests have no rows: unit tests per module, the replay of
the Go probe's goldens (`scripts/gen-go-goyaml`: 625 parse, 640 differential and 77 serde
goldens, `crates/gadk-goyaml/tests/`) and `gadk_platform::go_format_float_g`'s table
(`crates/gadk-platform/tests/go_format_float_g.rs`).

Not applicable (Go-reflection features with no serde analogue; their Go tests and table rows are
skipped with these reasons):
- the `Marshaler`, `Unmarshaler` and `obsoleteUnmarshaler` interfaces;
- the `IsZeroer` interface (`omitempty` is `skip_serializing_if`, which may call
  `NodeData::is_zero`);
- `encoding.TextMarshaler` / `encoding.TextUnmarshaler`;
- the `,flow` struct tag option;
- `Decoder.KnownFields` (strict mode);
- the `time.Time` and `time.Duration` reflection special cases (gadk types choose their own serde
  form; a `GoValue::Timestamp` still encodes and decodes as Go's `time.Time` in an
  `interface{}`).

Out of scope:
- ADK-Go's users of yaml.v3 (`internal/configurable`, the conformance record/replay plugins,
  `cmd/internal/adkcli`): sub-project 6c-2;
- byte-identity for gadk-genai / ADK model types encoded through serde (Go's genai structs carry
  no yaml tags; gadk-genai skips empty fields and writes bytes as base64): 6c-2's record plugin;
- a public (crates.io) API, and `gadk-tools`' use of `serde-saphyr` (unchanged).

Accepted divergences (each annotated `// Divergence (ledger 6c-1)` where it lives, unless noted):

Nesting depth (plan decision D7):
- Parsing accepts yaml.v3's depth (the composer runs on an explicit stack; past 10000 the scanner's `exceeded max depth of 10000`), but every recursive walk stops past 127 nested collections with `yaml: exceeded max depth of 127` instead of overflowing the thread's stack: the node encoder (`marshal_node`, `Encoder::encode_node`, a `Document` value inside a serde value), the serde `Serializer` (capture and walk, on the encoder's shared depth; a variant's `{variant: …}` counts as one mapping), the serde `Deserializer` and the `GoValue` decoder (an alias expansion counts as a level). Go's growable goroutine stacks let these walks go as deep as the scanner allows; 127 is the workspace-wide nesting policy (serde_json's limit). The four 10000-level `limitTests` rows that Go decodes expect this error from `unmarshal::<GoValue>` after checking that `unmarshal_node` accepts them — `crates/gadk-goyaml/src/error.rs` (`MAX_WALK_DEPTH`), `crates/gadk-goyaml/src/encode.rs` (`Encoder::node`), `crates/gadk-goyaml/src/ser.rs` (`enter`, `nested`), `crates/gadk-goyaml/src/de.rs` (`DecodeState::descend`), `crates/gadk-goyaml/src/parity_tests/yaml_v3_limit.rs` (`test_limits`).

Go strings that are not UTF-8:
- `NodeData::value` is a Rust `String`: a Go `Node.Value` may hold any bytes, but parsed values are always UTF-8 (the reader rejects invalid input), so only hand-built Go nodes differ. Hence `NodeData::set_string` (takes `&str`) never reaches Go's `!!binary` branch for invalid UTF-8, and the node encoder's `!utf8.ValidString(node.Value)` branch (the `!!binary` `failf` texts, else `!!binary` + base64) cannot occur; the serde path's `stringv` ports that branch in full. `nodeTests[7]` and `setStringTests[5]` are skipped for this — `crates/gadk-goyaml/src/node.rs` (`NodeData::value`, `NodeData::set_string`), `crates/gadk-goyaml/src/encode.rs` (`Encoder::node_unguarded`).
- `GoValue::Bytes(Vec<u8>)` holds a `!!binary` value whose decoded bytes are not UTF-8 (Go yields a `string` of those bytes; spec R5); it encodes back as `!!binary` like Go's string — `crates/gadk-goyaml/src/value.rs` (`GoValue::Bytes`).
- A tag whose `%`-escapes decode to bytes that are not UTF-8 keeps them in Go's string; here the invalid sequences become U+FFFD (reachable only through such escapes; no golden hits it) — `crates/gadk-goyaml/src/node.rs` (`go_string`).
- A non-UTF-8 `!!binary` value decoded into a Rust `String` field gets U+FFFD per invalid sequence (Go stores the raw bytes; `unmarshalTests` rows 142–143 are adapted) — `crates/gadk-goyaml/src/de.rs` (`go_string_of`).
- A `TypeError` line cuts a long value after 7 bytes even inside a UTF-8 sequence, as Go does; Go prints the raw bytes, the port shows U+FFFD there — `crates/gadk-goyaml/src/de.rs` (`DecodeState::terror`).

Type names in error texts (serde exposes no Go type):
- A struct is named by its bare serde name (Go: package-qualified, `main.Inner`) in `cannot unmarshal … into T`, `field X already set in type T` and `duplicated key 'k' in struct T`; the probe's serde goldens adapt 4 such texts (`main.X` → `X`) — `crates/gadk-goyaml/src/de.rs` (`Mode::go_name`, `MapWalk::next_yield`), `crates/gadk-goyaml/src/ser.rs` (`StructCapture::add_key`).
- A sequence target is named `[]interface {}` and a map target `map[string]interface {}` (Go names the element types: `[]int64`, `[]yaml.Node`, `[2]int`, `map[string]int64`); a byte buffer is `[]uint8` as in Go; the serde goldens adapt one text (`[]yaml.Node` → `[]interface {}`) — `crates/gadk-goyaml/src/de.rs` (`SeqWant::go_name`, `Mode::go_name`).

serde forms Go has no counterpart for:
- `#[serde(flatten)]` is rejected both ways with `Error::Unsupported`: on encode serde derive serializes such a struct as a map of unknown length (`serialize_map(None)`, also rejected for a custom `Serialize`: `serde flatten / maps of unknown length are unsupported`); on decode `serde flatten is unsupported (struct X)` — `crates/gadk-goyaml/src/ser.rs` (`Capture::serialize_map`), `crates/gadk-goyaml/src/de.rs` (`NodeDe::deserialize_map`).
- An `Option<Document>` field (Go `*yaml.Node`) receives the node like a `Document` field; Go checks for `yaml.Node` before `prepare` only, so a non-null value into a `*yaml.Node` is decoded as an ordinary struct there — `crates/gadk-goyaml/src/de.rs` (`NodeDe::deserialize_newtype_struct`).
- `NodeData::is_zero` cannot tell Go's nil `Content` from an empty non-nil one (an empty `Vec` is Go's nil) — `crates/gadk-goyaml/src/node.rs` (`NodeData::is_zero`).

Go panics returned as errors:
- An inline-map key equal to a struct field key returns `Error::Unsupported("cannot have key \"k\" in inlined map: conflicts with struct field")` (Go panics with that text; `handleErr` re-panics non-`yamlError` values), and two serde fields with one YAML key return `Error::Unsupported("duplicated key 'k' in struct T")` (Go's `getStructInfo` panic) — `crates/gadk-goyaml/src/ser.rs` (`StructCapture::finish`, `StructCapture::add_key`).
- A value is captured before its first event is emitted, so a value that fails while being captured (inline-map conflict, flatten, a serde value nested too deep) leaves no partial document in an `Encoder`'s stream, where Go panics part-way through the document. A failure during the walk that follows does not have this guarantee: a `Document` field whose nodes nest too deep (its depth is counted only on the walk) fails after events were already emitted, so the stream keeps that partial document and the `Encoder`'s later calls fail, as after Go's mid-document panic — `crates/gadk-goyaml/src/ser.rs` (`marshal_doc`).

Timestamps (plan decision D6):
- `GoValue::Timestamp` is a `chrono::DateTime<chrono::FixedOffset>`, so gadk-goyaml depends on `chrono` (workspace) besides `serde` and `base64` (the spec named only those two; Go's `time.Time` needs a datetime type). Output is RFC3339Nano via `gadk_platform::go_format_rfc3339_nano`, as Go's `timev` (not annotated: no behaviour differs beyond the next entry).
- Go's `time.Parse` accepts zone offsets up to `±24:60` (25 h); chrono's `FixedOffset` must be under 24 h, so such a text does not resolve to `!!timestamp` here and stays `!!str` (three rows of the resolve unit test carry Go's value) — `crates/gadk-goyaml/src/resolve.rs` (`time_parse`).

I/O errors:
- `input error: …` and `write error: …` end with the `std::io::Error`'s `Display`: Go's `err.Error()` for a message-only error (`io::Error::other("boom")` ↔ `errors.New("boom")`), but Rust's text for an OS error (e.g. `… (os error 28)`) — `crates/gadk-goyaml/src/reader.rs` (`yaml_parser_update_raw_buffer`), `crates/gadk-goyaml/src/writer.rs` (`yaml_emitter_flush`).
- The read handler follows `std::io::Read`, not Go's `io.Reader`: a read returning `Ok(0)` is the end of input (Go ends only on `io.EOF` and treats `(0, nil)` as "no data yet", reading again), and an `ErrorKind::Interrupted` read of a `Decoder`'s reader is retried (Rust-only; Go has no such error). An `Interrupted` error that is not retried (from a handler other than the reader's) is reported as `input error: …` like any other — `crates/gadk-goyaml/src/api.rs` (`yaml_reader_read_handler`), `crates/gadk-goyaml/src/reader.rs` (`yaml_parser_update_raw_buffer`).

Not annotated (decided in the spec, or no Go-observable effect):
- `unmarshal` / `from_node` / `Decoder::decode` return only `Err(Error::Type)` where Go also returns the partly filled value; `from_node_partial` returns `(T, Option<TypeError>)` for callers that need Go's behaviour (spec R7; `TestUnmarshal` and `TestDecoderSingleDocument` are adapted for it).
- Go zero-fills absent keys; a serde struct without container `#[serde(default)]` (or `Option`/`default` fields) fails with serde's ``missing field `x` `` (`Error::Custom`; spec R7).
- serde forms the spec leaves open: a unit struct encodes as `{}`; `()` and `None` as `null`; a `char` as a one-character string; a unit variant as its name; newtype, tuple and struct variants as a one-key mapping `{variant: …}` (struct-variant keys via `Options::key_for(<variant>, field)`); `i128`/`u128` are serde's `i128 is not supported`.
- `invalid map key: …` for a `map[interface{}]interface{}` key that is itself a map lists the inner keys ordered by kind, then text; Go's fmtsort orders mixed-type keys by type-descriptor address (no golden or test row hits it).
- A `Decoder`'s later document that aliases an anchor of an earlier one carries a copy of the target (`Document::subtree`); Go points into the earlier tree (pointer identity only).
- An event style outside Go's scalar styles is emitted plain where Go panics `unknown scalar style` (yaml.v3's encoder never produces one).
