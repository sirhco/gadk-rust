Accepted divergences (each annotated where it lives; a replay delta quotes the line it cites):

A2A (`web/a2a.rs`):
- The A2A 0.3 endpoint (`/a2a/invoke`) is not served: gorilla's 404, which the request logger does not log; the agent card has none of its 0.3 union fields (top-level `url`, `protocolVersion`, `preferredTransport`, the 0.3 interface, `capabilities.pushNotifications`).
- A2A answers are a2a-rs's JSON (compact, a2a-rs's key order; Go: a2a-go's, the card pretty-printed), and the card endpoint adds `Cache-Control: max-age=300` and an `ETag` (the card version).
- A2A v1 requests without an `A2A-Version` header are refused with JSON-RPC error `-32009` (`version not supported: 0.3`; a2a-rs reads a missing header as 0.3); a2a-go serves them as v1.
- A2A task results lack Go's merged status-update metadata (`adk_app_name`, `adk_session_id`, `adk_user_id`, the ADK extension key): a2a-rs's task store keeps only a `Task` event's own metadata (ledger 5b).
- The card endpoint's other methods are a2a-rs/axum's: `HEAD` → 200 without a body (Go 405), `OPTIONS`/`POST` → 405 with `Allow` (Go: `OPTIONS` 200 with the CORS headers); a request `Origin` is echoed with `Access-Control-Allow-Credentials: true` and `Vary: Origin` (Go `*`). A non-POST on the JSON-RPC endpoint gets axum's 405 (Go: a JSON-RPC `InvalidRequest` error).
- Go's one `A2AOptions` list is two ordered lists, `Config.a2a_options` (`A2AHandlerOption`: configure a2a-rs's default handler) then `Config.a2a_wrappers` (`A2AHandlerWrapper`: wrap the handler); Go `a2asrv.RequestHandlerOption`s with no a2a-rs equivalent cannot be expressed.

Telemetry (`telemetry.rs`; the providers' own divergences are ledger 7a's):
- `Config.telemetry_options` are Go's `TelemetryOptions` (gadk-telemetry options); the Rust-only `Config.telemetry_layers` adds `tracing` layers to the launcher's subscriber after the providers' bridge layer (Go's `api` sub-launcher appends the REST server's debug span and log processors to `TelemetryOptions`; gadk's adds its debug layer to `telemetry_layers`).
- An existing global `tracing` subscriber is kept and the launcher logs that its telemetry layers were not installed (Go always replaces the global OpenTelemetry providers).
- Only the global tracer provider is set: OpenTelemetry Rust has no global logger provider.
- `telemetry shutdown failed: <err>` carries opentelemetry_sdk's provider error (`Operation failed: Shutdown errors: [InternalFailure("<processor error>")]`); Go prints the processor's error.

Console (`console/mod.rs`, `console/hitl.rs`):
- tokio's Ctrl-C handler stays installed after the console's `run` returns (Go's `signal.NotifyContext` stop restores the default).
- A cancellation during a turn ends `run` at once (Go lets the runner surface its context error, which may print `AGENT_ERROR: context canceled` first).
- JSON numbers in HITL replies stay integers where Go decodes `float64` (the serialized function response is the same text).
- A stdin read error other than EOF is returned from `run` (Go `log.Fatal`s the process); stdin is read on a dedicated thread that stays blocked after `run` returns (Go: a goroutine).
- The tool-confirmation prompt never prints the `toolConfirmation` hint: gadk's call args are JSON, and Go prints the hint only when they were decoded from JSON into a map (e.g. a remote A2A sub-agent's events); for a local tool Go's args hold the `ToolConfirmation` struct and Go prints the same fallback.

Web server (`web/mod.rs`, `web/serve.rs`, `web/router.rs`):
- The web launcher prints the sub-launchers' `UserMessage` lines in declaration order (Go iterates a map; the fixtures sort them, N4).
- HTTP timeout semantics where hyper differs from `net/http`: an expired HTTP/2 idle connection is dropped without GOAWAY; an HTTP/2 stream past `-write-timeout` is cancelled and reset (Go lets the handler run, then resets); a handler not reading its body past `-read-timeout` is not cancelled (Go cancels the request context through the background read); a write past the deadline aborts the connection (Go: the write fails and the connection closes after the handler returns — the same wire result).
- A WebSocket upgrade (`/run_live`) is logged by the request logger when its 101 is sent (Go: when the handler returns at the end of the session).
- Listen errors other than address-in-use and permission-denied carry Rust's I/O error text after `listen tcp <addr>: `.
- Go's `http: Accept error: %v; retrying in %v` backoff is applied to every accept error (Go retries only `Temporary` ones and returns the others).
- Status texts and headers that come from hyper or a2a-rs rather than Go (each named by a replay delta).

Sub-launchers (`web/api.rs`, `web/triggers/*.rs`, `web/webui/*.rs`):
- `setup_subrouters` without a session service (never the case through `Run`, which fills every service first): `api` fails with `failed to create REST server: no session service configured`, `a2a` and the triggers use an in-memory one (Go passes the nil service on).
- Request-body JSON syntax and type errors keep serde's text after Go's prefix (ledger 5a; Go's `encoding/json` words them differently, e.g. `unexpected EOF`).
- `-trigger_max_retries` and `-trigger_max_concurrent_runs` above 2^31-1 are clamped to `i32::MAX` (Go `int`).
- Only Go's built-in MIME table is used (Go also reads the host's MIME files: identical for the bundle's extensions on macOS's `/etc/apache2/mime.types`); a multipart byte-range boundary comes from a non-cryptographic source (same format).

Flags (`gadk_platform::go_flag`):
- Go `flag` panics on a flag name that starts with `-`, contains `=` or is defined twice; `gadk_platform::go_flag` writes Go's message line and ignores the definition (launcher flag names are static, so this never fires).
