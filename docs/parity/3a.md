# Parity ledger — sub-project 3a

ADK-Go commit: see `docs/parity/ADK_GO_COMMIT`. Test-name rule: see the 1b spec § Parity tooling.

Rows below the table header are generated by `python3 scripts/parity-check --ledger 3a --generate`
from annotations in each Go test file's Rust target. Do not edit rows by hand:
- `fn test_foo` in the target → `ported`; a `// parity: adapted: <reason>` line within the 3 lines
  above the `fn` → `ported (adapted: <reason>)`;
- a line `// parity: skipped TestFoo: <reason>` in the target → `skipped`.

`model/anthropicmodel/anthropicmodel_test.go` is ported by several tasks, so its target is the
test directory `crates/gadk-anthropic/tests/model_anthropicmodel_anthropicmodel/` (`main.rs` and
one module per group of tests); a row's Rust file is the file that holds the `fn` or the skip
line. `TestAgentRunner_MultiTurnImageAndTool` needs the runner, so it lives in
`crates/gadk/tests/model_anthropicmodel_agent_runner.rs` and its row is `skipped` with that
reason (expected, not a gap). `model/apigee/apigee_test.go`'s target is
`crates/gadk-gemini/tests/model_apigee_apigee.rs`. The recordings `TestGenerate_Anthropic.httprr`
and `TestGenerate_Vertex.httprr` are under
`crates/gadk-anthropic/tests/testdata/model/anthropicmodel/testdata/`,
`TestAgentRunner_MultiTurnImageAndTool.httprr` under
`crates/gadk/tests/testdata/model/anthropicmodel/testdata/`.

Accepted divergences (each annotated where it lives):
- the `User-Agent` on the Anthropic backend is gadk's, not `Go-http-client/1.1` (scrubbed in
  replay); on Vertex, `x-goog-api-client` and `user-agent` carry gadk's
  `gadk_platform::tracking_header()` rather than `google-adk/<version> gl-go/<go version>`;
- the SDK's `X-Stainless-*` headers are not sent;
- Go's `ClientConfig.RequestOptions`, `TokenSource` and `Logger` are not ported: their subtests
  are adapted to `base_url`, `headers`, `http_client`, `credentials` and `tracing`, or skipped
  with a reason;
- `MaxTokens`, `MaxRetries` and `HTTPOptions.Timeout` are unsigned (`u32`, `Duration`), so Go's
  negative-value subtests are adapted;
- retry jitter uses `rand`; tests assert bounds, as Go's do;
- cancellation is by dropping the response stream (`LlmRequest` carries no context): Go's
  cancelled-context subtests are adapted;
- `tracing` events replace Go's `slog` warnings;
- with several extra keys in a tool's `input_schema`, gadk writes them sorted; the SDK appends
  them in Go map order (random).
