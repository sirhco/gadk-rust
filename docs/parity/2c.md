# Parity ledger — sub-project 2c

ADK-Go commit: see `docs/parity/ADK_GO_COMMIT`. Test-name rule: see the 1b spec § Parity tooling.

Rows below the table header are generated by `python3 scripts/parity-check --ledger 2c --generate`
from annotations in each Go test file's Rust target (`crates/*/tests/<target>.rs` or
`crates/*/src/parity_tests/<target>.rs`, where `<target>` is the Go path without `_test.go`, with `/`
replaced by `_`). Do not edit rows by hand:
- `fn test_foo` in the target → `ported`; a `// parity: adapted: <reason>` line within the 3 lines
  above the `fn` → `ported (adapted: <reason>)`;
- a line `// parity: skipped TestFoo: <reason>` in the target → `skipped`.

Go files in package `mcptoolset` (internal tests), and `auth_session_test.go` (package
`mcptoolset_test`, which uses `export_test.go`'s `SetSessionBoundsForTest`/`SessionCountForTest`),
have `#[cfg(test)]` targets under `crates/gadk-mcp/src/parity_tests/`. `set_test.go` (package
`mcptoolset_test`) drives an LLM agent, the runner and Gemini, so its target is
`crates/gadk/tests/tool_mcptoolset_set.rs`; it replays the 11 recordings under
`crates/gadk/tests/testdata/tool/mcptoolset/testdata/`.

Accepted divergences (each annotated where it lives):
- Go's legacy SSE client transport is not ported: rmcp has no SSE client;
- seven `TestMCPToolRunContent` table rows are not ported, because rmcp's `ContentBlock` cannot
  represent them: the five nil-content rows, a resource carrying both text and a blob, and
  unsupported content (each named in a comment in the table);
- invalid base64 in image, audio or blob data counts as 0 bytes;
- a `user-agent` set in a caller's `reqwest::Client` default headers is not merged with the
  tracking tokens: the tracking labels override it;
- reqwest has no process-wide default client (Go `http.DefaultClient`), so `Endpoint` starts
  every factory from a fresh `reqwest::Client::new()`;
- header names in the session key are lowercase (`http::HeaderName`), where Go canonicalizes them;
  Go's `auth: provider returned nil credential` cannot occur (a provider returns an `Arc`);
- `tracing` events replace Go's `log.Printf` lines;
- rmcp 3.9 puts `_meta.progressToken` on every request, where go-sdk adds the SDK-owned
  `io.modelcontextprotocol/{protocolVersion,clientInfo,clientCapabilities}` keys; the
  `MetadataProvider` reserved-key rule is unchanged, and the `adk-mcp-client` client info is
  checked where rmcp sends it (the `initialize` handshake);
- a `CallContext` carries only a `CancellationToken`, so Go's `context.DeadlineExceeded` waits
  end, through a timer, in `Error::Cancelled` (`context canceled`);
- `TestIdentityOnlyContext*` and `TestAuthDoesNotRetainInvocation` are adapted to the explicit
  `AuthContext` design: a session keeps the creating caller's identity, never its invocation; a
  `ReadonlyContext` always carries an identity, so Go's caller without one is
  `CallContext::background()`;
- gadk's `Context` carries no request-scoped values (Go `context.WithValue`), so a
  `MetadataProvider` derives per-call values from the tool context it is handed;
- Go's confirmation-provider branch on `args.(Input)` never matches (args are the decoded JSON
  object) and is not ported.
- a JSON-RPC error answering `tools/call` reads `failed to call MCP tool "x" with err: Mcp error:
  <code>: <message>` (rmcp's `ServiceError::McpError` text, `(<data>)` appended when present),
  where Go's reads `… with err: calling "tools/call": <message>` (go-sdk's `call` wrapping);
- `Error::is_connection_closed` also matches rmcp's `ServiceError::TransportClosed`, which stands
  for go-sdk's `ErrConnectionClosed` wrapping of a call in flight when its connection closes.

Rust-only tests (no Go counterpart, so no rows):
- `crates/gadk-mcp/src/client_tests.rs`: pagination, restart after a reconnect, the
  double-reconnect text, ping reuse, the failed-refresh text, cancelling an in-flight call or
  listing (returns at once, keeps the session);
- `crates/gadk-mcp/src/http_tests.rs`: an HTTP 404 reaches the refresher with
  `reinit_on_expired_session(false)`; a 401 with and without `WWW-Authenticate` refreshes once
  and replays; a second 401 is returned; credential errors carry the `auth: …` text; a refresh
  error that is an apply error still degrades to the rejection; a credential's `user-agent` is
  merged after the tracking tokens;
- `crates/gadk-mcp/tests/child_process.rs`: a child-process server through
  `McpTransport::Command`, killed and reconnected, by hand and through `gadk_mcp::new`, the
  toolset and its tool (Unix only);
- `crates/gadk-mcp/src/tool_tests.rs`: `McpTool` against a fake `McpClient`;
- `crates/gadk-mcp/src/set_tests.rs`: the toolset over the in-memory server (list, call, close,
  `tools()` cancellation);
- `crates/gadk-auth/src/transport.rs` unit tests of `apply_credential`, `refresh_credential` and
  `is_auth_rejected`;
- `crates/gadk/tests/facade_mcp.rs`: `gadk::mcp` resolves through the façade, and a façade
  toolset lists and calls an in-memory server's tools.
