Accepted divergences (each annotated `// Divergence (ledger 7b-2)` where it lives; 15):

BigQuery Storage Write (gapic client and stream writer):
- The AppendRows `trace_id` is `gadk-bq-logger-rust/<gadk-agentanalytics version>` (Go: `google-adk-bq-logger-go/<ADK-Go version>`) — `crates/gadk-agentanalytics/src/write/stream_writer.rs` (`STREAM_WRITER_TRACE_ID_PREFIX`).
- `x-goog-api-client` on BigQuery Write calls is gadk's tracking header (`gadk_platform::tracking_header()`), not Go's `gl-go/… gapic/… gax/… grpc/…` — `crates/gadk-agentanalytics/src/write/gapic.rs` (`call_metadata`).
- A failed BigQuery Write call's status text is `rpc error: code = … desc = …` alone: gax's `Invoke` wraps each failed attempt with `apierror.FromError`, whose `Error()` text appends the status details (`ErrorInfo`, `DebugInfo`, …); the google.rpc error-details protos are not generated, so gadk's status carries the code and message only — `crates/gadk-agentanalytics/src/write/gapic.rs` (`invoke`).
- AppendRows opens like grpc-go's `NewStream` (the call starts on a driver task without waiting for the server, so server statuses arrive at `recv` and `send` on an ended stream returns `EOF`), but a channel that cannot connect fails the stream at its first `recv` (`Unavailable`) instead of failing the open, so gax's open retry on `Unavailable` does not cover connection failures (grpc-go fails `NewStream` fast in TRANSIENT_FAILURE and gax retries it); the stream writer's own retries apply — `crates/gadk-agentanalytics/src/write/gapic.rs` (`open_append_rows`).
- AppendRows request field order: prost encodes the `rows` oneof (field 5) after `trace_id` (field 6), Go's `proto.Marshal` in field-number order; every field's bytes, the decoded message and the encoded size are Go's (protobuf parsers accept any order) — `crates/gadk-agentanalytics/src/write/stream_writer.rs` (`append_rows_request`).
- Opening a stream without a write client fails with `writeClient is nil` (status `Unknown`, retried like any non-permanent open error) where Go calls AppendRows on its nil gapic client and panics — `crates/gadk-agentanalytics/src/write/stream_writer.rs` (`StreamWriter::append`, the open).
- The `BigQuery response: %s` log line writes prost's `Debug` form of the response, where Go writes its prototext `String()` (whose format protobuf-go deliberately randomizes) — `crates/gadk-agentanalytics/src/batch_processor.rs` (`append_chunk_boxed`).

Arrow record batches:
- A row without a timestamp: arrow-go's record batch keeps the non-nullable `timestamp` field with Go's NULL in it; arrow-rs's safe constructors reject that (only `unsafe` `RecordBatch::new_unchecked` would allow it), so the in-memory batch's schema declares such a field nullable. The IPC record batch message BigQuery receives (no schema) carries the same field nodes and NULL validity bits — `crates/gadk-agentanalytics/src/write/arrow_batch.rs` (`nullable_where_null`).
- Record batch message bytes are arrow-rs's encoding (compared with arrow-go's by decoding, as 7b-1's schema bytes): same 8-byte-aligned buffers, field nodes, buffer order and body bytes, but a different flatbuffer header layout (an empty batch's is 8 bytes shorter) and validity bitmaps of `ceil(rows / 8)` bytes where arrow-go writes its builder's allocation, so a message is at most 63 bytes per NULL-bearing column shorter than Go's, and the serialized request size compared with the 9 MiB limit follows — `crates/gadk-agentanalytics/src/write/arrow_batch.rs` (`serialize_record`).

GCS offloader:
- `X-Goog-Api-Client` client-version tokens are gadk's tracking header (`gadk-rust/<v> rust/<v>`) in place of Go's `gl-go/<go> gccl/<storage>` / `gdcl/<api>`; the `gccl-invocation-id/…` and `gccl-attempt-count/…` tokens and their order are Go's — `crates/gadk-agentanalytics/src/offload/gcs.rs` (`client_version_tokens`).
- The multipart boundary is two v4 UUIDs' hex digits (12 fixed bits) where Go draws 30 bytes from `crypto/rand`; the shape `^[0-9a-f]{60}$` is Go's — `crates/gadk-agentanalytics/src/offload/gcs.rs` (`multipart_boundary`).
- A 2xx object reply is only required to be JSON; Go decodes it into `storage/v1` `Object` and fails on a field of the wrong JSON type (the returned URI is the bucket and path either way) — `crates/gadk-agentanalytics/src/offload/gcs.rs` (`decode_object`).

Upload orchestration:
- An offloader panic's `%T` is `string` for `&str` / `String` payloads, else `unknown` (Rust has no runtime type name of a panic value), and Rust's panic hook still reports the panic before it is caught, where Go's `recover` is silent — as 7b-1's content-formatter panics — `crates/gadk-agentanalytics/src/offload/uploads.rs` (`upload_payload`).
- `extensionForMIME` beyond `mimeExtensions` answers from Go's built-in MIME table alone (the first sorted extension per type); Go's `mime.ExtensionsByType` also consults the host's MIME tables (`/etc/mime.types` and the like) and `mime.AddExtensionType`, so a type only the host knows gets `.bin` — `crates/gadk-agentanalytics/src/offload/uploads.rs` (`extension_for_mime`).
- `safeUploadErrorSummary`'s `error type %T`: an `Error::Other` (a custom offloader's own error type) or an Arrow error is `error type error` (Go names the dynamic type, e.g. `agentanalytics.zzCustomErr`); the other error kinds map to Go's types (`*errors.errorString`, `*fmt.wrapError`, `*status.Error`, `*googleapi.Error`, …) — `crates/gadk-agentanalytics/src/offload/uploads.rs` (`go_error_type`).

Not annotated (no Go-observable effect, or not applicable):
- Go's negative `time.Duration` settings (`ShutdownTimeout`, `RetryConfig.InitialDelay`) and negative `int` sizes / ordinals in the helper tables have no Rust value: the `validate_config` golden skips `retry_initial_delay_negative` and pins `shutdown_timeout_negative` after `with_defaults`; the helper goldens skip the `-1` / `-2` cases. 7b-1's ledgered "negative `time.Duration`" divergence covers them.
- Go's `context.Context` is the crate's `Context`: grpc-go outgoing metadata is its only modeled value; `Err` / `Cause` are fixed at the instant a deadline passes or a cancel happens (a child whose own timeout passed before its parent ended keeps its own cause); `AfterFunc` runs `f` on a spawned task.
- Go's gax "never retry an `x509: certificate signed by unknown authority` error" text check is not ported (rustls/tonic never produce that text).
- The fake write server sees a canceled AppendRows stream's requests end just before its cancellation (h2 `RST_STREAM` after the request body); grpc-go servers see only the cancellation. Hooks that must tell them apart wait on `cancelled()`. Test-only.
- grpc-go's `content-type`, `grpc-accept-encoding` and `user-agent` stream headers, and tonic's equivalents, are transport artifacts (excluded from the metadata comparison, as 7b-1's REST transport headers).
- `User-Agent` on GCS requests is gadk's tracking header (7b-1's "REST request headers" entry).
- `WriteClient::close` leaves AppendRows streams already open running until they end (grpc-go's `ClientConn.Close` hard-closes them); new calls fail with `ErrClientConnClosing` as in Go. The plugin finishes its streams before it closes the client, so this is not observable there.
- The Go tests that set processor fields after construction (`Logger`, `MaxRetries`, `uploadTimeout`, …) use construction-time config or `pub(crate)` setters (adapted rows); Go's `-race`-only concurrency tests run on a multi-threaded runtime.
