# Parity ledger — sub-project 2a

ADK-Go commit: see `docs/parity/ADK_GO_COMMIT`. Test-name rule: see the 1b spec § Parity tooling.

Rows below the table header are generated by `python3 scripts/parity-check --ledger 2a --generate`
from annotations in each Go test file's Rust target (`crates/*/tests/<target>.rs` or
`crates/*/src/parity_tests/<target>.rs`, where `<target>` is the Go path without `_test.go`, with `/`
replaced by `_`). Do not edit rows by hand:
- `fn test_foo` in the target → `ported`; a `// parity: adapted: <reason>` line within the 3 lines
  above the `fn` → `ported (adapted: <reason>)`;
- a line `// parity: skipped TestFoo: <reason>` in the target → `skipped`.

Package-internal Go tests, and tests of modules that are private in Rust (`internal/ranksearch`,
`tool/exampletool`, `tool/toolsearch`, `tool/skilltoolset/instruction_test.go`,
`tool/skilltoolset/internal/skilltool` and `tool/skilltoolset/skill`), have `#[cfg(test)]` targets
under `crates/gadk-tools/src/parity_tests/`; `plugin/retryandreflect` has one under
`crates/gadk-engine/src/parity_tests/`. `examples/toolsearch/main_test.go` is ported in
`crates/gadk/tests/examples_toolsearch_main.rs`.

`tool/toolutils/toolutils_test.go` keeps its rows in `docs/parity/1b.md`. The `TestTypes` cases of
`tool/tool_test.go` that 1b left out (the `geminitool` and `loadartifactstool` cases) are ported in
`crates/gadk-tools/tests/tool_tool_types.rs`; that file is not a ledger target, and the
`tool/tool_test.go` `TestTypes` row stays in `docs/parity/1b.md` unchanged.

Accepted divergences (no Go test asserts them):
- retryandreflect's `error_type` is the Rust variant path, not Go's `%T`;
- regex patterns outside Go's ranksearch test table may get different "pattern not run" texts;
- YAML parser error messages differ from yaml.v3's;
- frontmatter `build` output is formatted by serde-saphyr and is only required to round-trip.
