# Parity ledger — sub-project 4c

ADK-Go commit: see `docs/parity/ADK_GO_COMMIT`. Test-name rule: see the 1b spec § Parity tooling.

Rows below the table header are generated by `python3 scripts/parity-check --ledger 4c --generate`
from annotations in each Go test file's Rust target. Do not edit rows by hand:
- `fn test_foo` in the target → `ported`; a `// parity: adapted: <reason>` line within the 3
  lines above the `fn` → `ported (adapted: <reason>)`;
- a line `// parity: skipped TestFoo: <reason>` in the target → `skipped`.

Targets: `session/vertexai/X_test.go` →
`crates/gadk-vertexai/src/parity_tests/session_vertexai_X.rs`, except `vertexai_test.go` → the
module directory `crates/gadk-vertexai/src/parity_tests/session_vertexai_vertexai/` (`convert.rs`
holds the conversion tests, `client.rs` the client tests). All reach the crate-private client,
conversions and test servers (`ReplayServer` on the 22 fixtures in
`crates/gadk-vertexai/testdata/replays/`, `FakeAgentEngine`), both on a 127.0.0.1 fake server.
The 9 files hold 35 `Test*` functions. `TestAiplatformToGenaiContentPreservesFunctionIDs` ports
as `test_aiplatform_to_genai_content_preserves_function_i_ds` (the name rule splits `IDs`).

Accepted divergences (each annotated where it lives):
- the Vertex AI `v1beta1` REST/JSON API instead of gRPC: the fixtures are converted from Go's gRPC
  recordings, and requests are compared with them as protobuf values;
- `SessionError::NotFound` drops Go's `"%q: …"` not-found detail and the service's prefixes
  (`failed to get session: …`, `failed to append event: …`, the create wait's
  `LRO for CreateSession failed: …`), which Go wraps around `ErrNotFound` with `%w`;
- `Get` runs `GetSession` and `ListEvents` concurrently and, when neither is not-found, reports
  the session's error before the events' error; Go's errgroup returns whichever failed first;
- memory's state time key is read as an RFC 3339 string, not a Go `time.Time` (so `%T` of an
  unparsable string is `string`); a parsable year-0000 time is sent as is, where Go's protojson
  refuses to marshal it;
- a retrieved memory without a `memory` field is an empty fact (Go would dereference nil);
- an empty `custom_metadata` map is not sent: gadk's field is a plain map, so an empty map and
  no map are one value, where Go sends `customMetadata: {}` for a non-nil empty map;
- memory's operation done without a result is plain success (Go matches the error string
  `unsupported result type <nil>: <nil>`);
- the append type error names `another Session implementation` where Go prints `%T`;
- `InvalidRequest` errors display with gadk's `invalid request: ` prefix before Go's text (the
  agentengine session methods, 5c, answer with Go's bare text: they drop the prefix);
- `Test_vertexaiService_AppendEvent_StructuralValidation`'s `nil_event` subcase is N/A (an
  `&mut Event` cannot be null); its `missing_author` / `missing_invocation_id` subcases run on
  `FakeAgentEngine` instead of recordings that never match;
- delete's and create's `context` cancellation is dropping the future;
- `VertexAiSessionService::new` returns `SessionError` and `VertexAiMemoryService::new` returns
  `MemoryError` (`Backend`, Go's wrapper texts `failed to create Vertex AI client: could not
  establish connection to the aiplatform server: …` and `newVertexAIClient failed:
  aiplatform.NewMemoryBankClient failed: …`), not a `VertexError`;
- an empty 2xx response body is read as `{}` (`client.rs`), where Go's protojson unmarshal of an
  empty body errors;
- strict protojson-scalar validation (`validate_scalars`) reports the first malformed field in a
  fixed field order, where Go reports the first in document order, and its error's raw token is
  serde_json's rendering, which can differ from Go's `RawString()` for exponent-form numbers and
  escaped strings;
- strict scalar validation applies to ListEvents responses (`session_event_to_event`);
  GetSession/ListSessions responses' `sessionState`/`updateTime` are read without it (Go's
  protojson would fail the whole call on a malformed scalar there; unreachable against a real
  engine).

Resolved in Go's favour over the spec (not divergences from Go; recorded because the spec says
otherwise):
- `ListSessions` and `ListEvents` send no `x-goog-request-params` header (Go's REST client sets
  none for them); `Content-Type: application/json` is sent on every call;
- operation polls are `GET {scheme://authority}/ui/{name}` with no query (no `$alt`), routing
  `name={operation name}`, each with a 10 s deadline within which a 503 is retried with gax
  backoff (500 ms ×2, cap 10 s) — the only retrying call;
- numbers in Struct-valued fields (state, state deltas, custom metadata, function
  args/responses, the raw event) are written as the JSON number Go prints for the float64 the
  value becomes (integral values below 1e21 stay integers; precision beyond 2^53 is lost, as
  in Go);
- a duplicate user-provided session ID fails with the real engine's 400 `INVALID_ARGUMENT`
  `Session with user-provided ID '{name}' already exists.` (the recording
  `Create_when_already_exists__it_fails`), not the spec's 409, in `FakeAgentEngine` too.
