# Parity ledger — sub-project 6b

ADK-Go commit: see `docs/parity/ADK_GO_COMMIT`. Test-name rule: see the 1b spec § Parity tooling.

Rows below the table header are generated by `python3 scripts/parity-check --ledger 6b --generate`
from annotations in each Go test file's Rust target. Do not edit rows by hand:
- `fn test_foo` in the target → `ported`; a `// parity: adapted: <reason>` line within the 3
  lines above the `fn` → `ported (adapted: <reason>)`;
- a line `// parity: skipped TestFoo: <reason>` in the target → `skipped`.

Scope: ADK-Go's deploy CLI `cmd/adkgo` (`adkgo deploy cloudrun`, `adkgo deploy agentengine`;
`cmd/adkgo/internal/deploy/{cloudrun,agentengine}`) and its helper package `internal/cli/util`
(`text_helpers.go`, `oscmd.go`), ported to the crate `gadk-cli` (binary `gadk`), plus the public
Reasoning Engine REST client `gadk_vertexai::reasoning_engine` it deploys through. All targets
live in `crates/gadk-cli/src/parity_tests/` (`cmd_adkgo_internal_deploy_cloudrun_cloudrun.rs`,
`cmd_adkgo_internal_deploy_agentengine_agentengine.rs`, `internal_cli_util_text_helpers.rs`).
`text_helpers_test.go` moved here from ledger 6, which listed it as skipped until this
sub-project. `internal/cli/util/flagset_helpers.go` is the launcher's (`gadk-launcher`'s
`flag_usage.rs`, ledger 6). gadk-cli's own tests (the command tree and pflag-compatible flags,
`oscmd` output, Cargo target resolution, the staged source and archive, the Cloud Run and Agent
Engine runs against a recording runner and a fake Vertex AI, and the binary end-to-end tests in
`crates/gadk-cli/tests/cli.rs`) have no Go counterpart and no rows.

Out of scope (not ported):
- `cmd/internal/adkcli` and `internal/configurable` (with the conformance record/replay
  plugins): sub-project 6c-2 (`docs/parity/6c-2.md`);
- a local build (Go's Cloud Run deploy compiles locally; gadk always builds remotely, see below)
  and any cross-compilation;
- live GCP tests: `gcloud`, `cargo build` of a fixture and Vertex AI are never run by the tests;
- re-exporting the CLI from the `gadk` façade crate.

Accepted divergences (each annotated `// Divergence (ledger 6b)` where it lives, unless noted):

Command tree and flags (`root.rs`, `deploy/cloudrun.rs`, `deploy/agentengine.rs`):
- The root texts name gadk (`CLI tool for use with gadk`, `gadk is a CLI tool …`; Go: `… ADK-GO`, `adkgo is …`) — `crates/gadk-cli/src/root.rs` (`SHORT`/`LONG`).
- No `completion` command (cobra adds one to every root); clap's `help` subcommand stands in for cobra's `help` — `crates/gadk-cli/src/root.rs` (`command`).
- Help and usage use clap's layout (`Usage: gadk deploy cloudrun [OPTIONS]`, `Options:`), not cobra's template; the error path prints the usage line and the argument list — `crates/gadk-cli/src/root.rs` (`usage`).
- A non-UTF-8 argument is a clap parse error (`Error: invalid UTF-8 was detected in one or more arguments` + usage); Go keeps the bytes and the shell-safe checks reject them later — `crates/gadk-cli/src/root.rs` (`execute`).
- `cloudrun`'s Long text says the image is built from the staged Cargo workspace (Go: "fed with locally compiled server executable containing Web UI static files") — `crates/gadk-cli/src/deploy/cloudrun.rs` (`LONG`).
- `-e/--entry_point_path` names a Cargo package (its directory or `Cargo.toml`) and its help says so (Go: "Path to an entry point (go 'main')") — `crates/gadk-cli/src/deploy/cloudrun.rs`, `crates/gadk-cli/src/deploy/agentengine.rs` (`command`).
- `-d/--source_dir` defaults to the Cargo workspace root and must be it or an ancestor of it; its help says so (Go: "defaults to current working directory") — `crates/gadk-cli/src/deploy/agentengine.rs` (`command`).
- The gadk-only `--bin` flag on both subcommands selects the package's binary target — `crates/gadk-cli/src/deploy/cloudrun.rs`, `crates/gadk-cli/src/deploy/agentengine.rs` (`command`).
- `fmt.Println(flags)` prints the receiver (Go: the package global `flags`; the same values from the command line) — `crates/gadk-cli/src/deploy/cloudrun.rs` (`deploy_on_cloud_run`), `crates/gadk-cli/src/deploy/agentengine.rs` (`AgentEngineFlags::go_v`).

Cargo target and image (`target.rs`, `stage.rs`):
- A Cargo binary target instead of a `main.go` entry point: Go splits the `main.go` path into build dir and file and strips `.go` into the executable name; gadk resolves the package, binary (`--bin`) and workspace root through `cargo metadata --format-version 1 --no-deps`, the binary standing in for Go's `execFile` and the package directory for Go's `srcBasePath`. The not-found, no-binary, several-binaries, unknown-`--bin` and `cargo metadata` failure texts are gadk's (Go has none), and a `Cargo.lock` at the workspace root is required — `crates/gadk-cli/src/target.rs` (`resolve`), `crates/gadk-cli/src/deploy/cloudrun.rs`, `crates/gadk-cli/src/deploy/agentengine.rs` (`compute_flags`).
- An extra shell-safe check of the package name (label `package name derived from --entry_point_path "<raw -e>":`), which reaches the builder's `RUN cargo build -p` line (Go has no package name) — `crates/gadk-cli/src/deploy/cloudrun.rs`, `crates/gadk-cli/src/deploy/agentengine.rs` (`compute_flags`).
- An out-of-root `path` dependency check (Go has none): a workspace member's `path` dependency outside the staged root (Cloud Run: the workspace root; Agent Engine: the archive root) is rejected before the temp dir exists (`path dependency "<p>" is outside "<root>" and would not be staged`) — `crates/gadk-cli/src/target.rs` (`check_path_dependencies`).
- Builder version chain: Go's go.mod `go` → `runtime.Version()` → `latest`; gadk's `rust-toolchain.toml` `[toolchain] channel` at the workspace root → `rust-version` (as `cargo metadata` resolves it) → the rustc that compiled gadk (`GADK_CLI_RUSTC_VERSION`, captured by `build.rs`) → `latest`; the legacy `rust-toolchain` file and dotted keys are not read, and a version must match `^[0-9]+(\.[0-9]+){0,2}$` (no Go `rcN` suffix) — `crates/gadk-cli/src/target.rs` (`builder_rust_version`).
- Builder image `rust:<ver>-bookworm` (`rust:bookworm` for `latest`) instead of `golang:<ver>` with `ENV GOTOOLCHAIN=auto` (rustup in the image honours `rust-toolchain.toml`, the equivalent) — `crates/gadk-cli/src/target.rs` (`builder_image`).
- Both targets build remotely in a two-stage Dockerfile (`WORKDIR /app/<ws>`, `COPY . /app/`, `RUN cargo build --release --locked --target-dir /gadk-target -p <pkg> --bin <bin>`), with the runtime `gcr.io/distroless/cc-debian12` (glibc) instead of `static-debian11` and `COPY --from=builder /gadk-target/release/<bin>  /app/<bin>` (Go's Cloud Run copies a locally compiled binary; its Agent Engine builder runs `go build`). `--target-dir` overrides a staged `build.target-dir`; a staged `build.target` breaks the `COPY` (README). `EXPOSE`, the comment and the `CMD` array are Go's — `crates/gadk-cli/src/stage.rs` (`dockerfile`).
- Staging and archive exclusions: every entry named `.git` or `target`, at any depth, and a temp dir nested in the root (Go's archive excludes `.git` and `adkgo`; Go's Cloud Run stages no source) — `crates/gadk-cli/src/stage.rs` (`EXCLUDED_NAMES`).
- The archive is written in-process (Go runs `tar -czf … -C <src> --exclude=.git --exclude=adkgo . -C <tmp> Dockerfile`): component-sorted entries, no `./` prefix and no root `./` entry, deterministic headers (fixed mtime, uid/gid 0, mode 0644/0755), symlinks stored as links, the generated `Dockerfile` appended last with mode 0644 — `crates/gadk-cli/src/stage.rs` (`SourceTree::write_tar_gz`).

Cloud Run (`deploy/cloudrun.rs`):
- `"Staging source"` replaces Go's `"Compiling server"` (a local `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build`): the workspace root is copied into the temp dir for a remote Cloud Build build; its printer lines (`Using <manifest dir> as entry point`, `Copying <root> to <temp>`, `Writing: <.gcloudignore>`) and error texts are gadk's, and a one-comment `.gcloudignore` is written when the workspace has none, so gcloud does not fall back to `.gitignore` — `crates/gadk-cli/src/deploy/cloudrun.rs` (`stage_source`).

Agent Engine (`deploy/agentengine.rs`, `gadk-vertexai/src/reasoning_engine.rs`):
- The archive root is `-d` or else the Cargo workspace root (Go: the working directory); a `-d` that is neither the workspace root nor an ancestor of it is rejected (`--source_dir "<d>" is neither the Cargo workspace root "<root>" nor an ancestor of it`); the workspace path below it becomes `WORKDIR /app/<ws>` and gets the shell-safe check (label `--source_dir`) — `crates/gadk-cli/src/deploy/agentengine.rs` (`compute_flags`).
- The archive step prints no `Running :` line and has gadk's error texts (`cannot read the source directory …`, `cannot read the generated Dockerfile: …`, `cannot write the source archive …`); the source's root `Dockerfile` is left out (Go archives it before the generated one, and the later entry wins on extraction) and a nested temp dir is excluded — `crates/gadk-cli/src/deploy/agentengine.rs` (`create_archive`).
- The update mask keeps Go's `spec.context_spec` path (as `spec.contextSpec`) although `contextSpec` is a top-level ReasoningEngine field — `crates/gadk-cli/src/deploy/agentengine.rs` (`update_agent_engine`).
- REST instead of gRPC: Go creates and updates the engine through the gRPC `aiplatform.NewReasoningEngineClient` dialled at `<region>-aiplatform.googleapis.com:443`; gadk sends Go's generated REST v1beta1 requests to `https://<location>-aiplatform.googleapis.com` (same `Sprintf`, no `global` special case; `$alt=json;enum-encoding=int`, `x-goog-request-params`, protojson bodies; the operation polled with `WaitWithInterval(…, time.Minute)`), so a failed call's text is the status form `rpc error: code = … desc = …` — `crates/gadk-vertexai/src/reasoning_engine.rs` (`ReasoningEngineClient::new`).

Process, output and I/O (`runner.rs`, `util/text.rs`):
- I/O error texts inside Go's wrapping texts are Rust's `io::Error` texts, not Go's `*PathError` (`fork/exec …`, `chdir …`, `mkdir …`, `open …`): a spawn failure other than the `LookPath` failure; `cannot create a temporary sub directory in '<abs>': …`; the Dockerfile write; `failed to clean temp directory <dir>: …`; `cannot read archive file: …` — `crates/gadk-cli/src/runner.rs` (`TokioRunner::run`), `crates/gadk-cli/src/deploy/cloudrun.rs` (`compute_flags`, `prepare_dockerfile`, `clean_temp`), `crates/gadk-cli/src/deploy/agentengine.rs` (`compute_flags`, `prepare_dockerfile`, `clean_temp`, `source_code_spec_and_methods`).
- A signal-terminated child names only the common signals (`hangup`, `interrupt`, `quit`, `illegal instruction`, `abort trap`/`aborted`, `floating point exception`, `killed`, `segmentation fault`, `broken pipe`, `alarm clock`, `terminated`; others `signal <n>`) and never appends ` (core dumped)` — `crates/gadk-cli/src/runner.rs` (`signal_name`).
- `center_string` pads a string wider than the width with nothing; Go's `strings.Repeat` panics on the negative count (no caller reaches it) — `crates/gadk-cli/src/util/text.rs` (`center_string`).

Notes (behaviour differences without a Go-observable effect; not annotated):
- Cloud Run's `prepare_dockerfile` removes an existing entry at the Dockerfile path before writing, so a copied root `Dockerfile` symlink is never followed; Go's `os.WriteFile` would truncate or follow it, but Go's temp dir never holds a copied Dockerfile.
- Cloud Run's `stage_source` and `prepare_dockerfile` return `no Cargo target: computeFlags has not run` when `compute_flags` has not resolved a Cargo target; Go's `prepareDockerfile` on such a receiver just writes a Dockerfile. Agent Engine's `prepare_dockerfile` instead falls back to an empty target (`unwrap_or_default`). Neither case is reachable from the command line, which always runs `compute_flags` first.
