Accepted divergences (each annotated where it lives):

Conversions (`convert`):
- A non-terminal status update whose message converts to no parts yields no event (`Ok(None)`); Go dereferences a nil `Content` (panic).
- JSON numbers in metadata stay integers where Go's `map[string]any` holds `float64`; the wire text is identical up to 2^53 (`test_metadata_two_way_conversion`).
- `unknown part type: …` / `not a file part: …` end in the Rust `Debug` form of the part, not Go `%v`; other JSON decode errors are serde_json's text.
- Custom metadata that is empty but non-nil in Go (`adk_custom_metadata: {}`) is omitted: a `serde_json::Map` cannot tell empty from nil.
- Go's case-insensitive JSON field matching when decoding typed data parts and metadata is not reproduced; serde matches the exact (camelCase) names.
- `event_to_message` always returns `Some` (Go's `nil` is only for a `nil` event).
- `PartContent::Raw` with an empty byte vector converts to a file part (Go: a nil `Raw` is `unknown part type`); a2a-rs cannot tell nil from empty bytes.
- An artifact update's metadata is never mutated in place; `artifact_update_visible_meta` reproduces the view Go's in-place merge leaves (`artifact_update_partial_follows_go`).

Server (`server::Executor`, identity):
- A non-streaming `SendMessage` yields no submitted `Task` (a2a-rs passes a submitted snapshot as `stored_task`; `a_non_streaming_send_yields_no_submitted_task`).
- Cleanup runs when the stream yields its terminal event, errors, ends or is dropped, as a task spawned on the current runtime (none: skipped with a log); it may start before a2a-rs stores the terminal event (the `server::cleanup` tests).
- The child-task cancel also triggers on a stored `canceled` task whose `pre_cancel_status` is input-required with pending long-running calls (a2a-rs `begin_cancel` sets `canceled` before `cancel` runs; `the_child_cancel_trigger_reads_the_pre_cancel_status`).
- Each child `CancelTask` is bounded by the 5 s cleanup timeout (Go's server path has no bound).
- The cleanup callback's card list leaves out remote sub-agents configured with a card provider (Go passes a nil entry).
- `owns_auth_scope` without `auth` attaches no credential scope to the child cancel (gadk's scope means "apply this provider's credential"; reachable only with a hand-built `A2AServerConfig`).
- A cancel aborts the task's running execution at once, as Go's cancelled context does, but the run is dropped rather than context-cancelled: `AfterExecuteCallback` is not called after a cancel (Go calls it with the failed `agent run failed: context canceled` status) and the invocation's cancellation token is not cancelled (`test_executor_cancel_after_event`, `a_cancel_stops_the_running_execution_and_both_cleanups_see_it_canceled`).
- a2a-rs fails a streaming subscription with `task <id> is in terminal state Canceled and cannot transition to <state>` (-32600) when an execution event is in flight as a cancel lands, instead of ending it with the `canceled` update (Go serializes the cancel through the execution's event queue); `test_a2_a_cleanup_propagation`'s server B therefore waits for its cancel before its next event.
- `before execute: callback returned nil context` and `failed to create a2a-executor plugin` cannot occur.
- a2a-rs passes only visible-ASCII header values as service params, so the identity layer drops a user ID outside visible ASCII (control characters, non-ASCII text such as `élodie`) with a warning, and the request runs as the anonymous `A2A_USER_<context_id>` user (`a_user_id_that_is_not_a_header_value_is_dropped`, `a_user_id_that_is_not_visible_ascii_is_dropped`).

Remote agent (`remoteagent`):
- gadk's default `RunConfig.streaming_mode` is `None`, so a remote agent run with a default config sends `SendMessage`; Go's zero `StreamingMode` is `""` (not `"none"`), with which the remote agent streams (`test_a2_a_cleanup_propagation` sets SSE explicitly).
- After-request callbacks see a non-A2A error (before-callback or converter error) as `A2AError::internal(<text>)`; Go passes the raw error.
- Before-request callbacks cannot change the outgoing request; after-request and OnEvent callbacks replace an event only by returning one (Go mutates in place).
- A dropped event stream runs cleanup and destroy on a spawned task after the drop (Go: before `Run` returns); without a tokio runtime they are skipped with a warning.
- The cleanup cause handed to `RemoteTaskCleanupCallback` is `Error::Message(<text of the last yielded error>)`; invocation cancellation gives `context canceled`; the callback gets no context and runs inside the auth scope only with `auth`.
- Invocation cancellation ends the response stream with a locally built `context canceled` error event.
- Invocation cancellation is observed only once the response loop starts: card resolution, client creation and the before-request callbacks run to completion on an already-cancelled invocation (Go's cancelled send context fails a fetched card's resolution early, with the provider's own error text).
- Without `auth`, the spawned end-of-run cleanup does not see a caller's ambient `AUTH_SCOPE` (crate-private; not reachable from outside the crate). A panic in a `remote_task_cleanup_callback` or in `destroy` during a normal finish is caught (a `JoinError`) and logged as `remote task cleanup failed` rather than propagated.
- `marshal_function_response_json` never yields `<unserializable>`, and there are no nil parts in `convertParts`/`presentAsUserMessage` (a `serde_json::Map` holds no NaN or cycle).
- Remote and workflow agents are described in agent cards as custom agents (as in Go; no special handling).

Auth and agent cards:
- The credential is applied once per call as request headers, not per redirect hop; reqwest drops `Authorization` when scheme, host or port changes, so on Go's allowed http→https same-host upgrade a bearer/basic/OAuth2 credential does not follow (API-key headers do).
- Mint/apply single-flight groups are kept per credential-provider `Arc` (a process registry), not per remote agent.
- A cancelled mint/apply wait is a dropped future: no `remoteagent: <what>: context canceled` error.
- Token-error redaction also covers reqwest status errors (the google-cloud-auth shape); `RetrieveError` (Go `oauth2.RetrieveError`) stays crate-private, so a user-written token source cannot opt in to Go's code-preserving form.
- Redirect checks parse URLs with `url` (WHATWG): `request_origin` omits explicit default ports and rejected URLs are skipped (`card_sends_in_clear` and the card checks use the Go `net/url` port, `gadk_platform::go_url`).
- `same_credential_target` compares WHATWG-normalized ports: an http→https upgrade with the same explicit default port (`http://h:80` → `https://h:80`, `http://h:443` → `https://h:443`) is refused where Go follows (equal explicit port strings); reqwest hands the redirect policy normalized URLs only (`an_upgrade_compares_whatwg_normalized_ports`).
- `redact_token_error`'s reqwest-status arm labels any HTTP status error as `oauth2: cannot fetch token: …`, also one that came from a credential's own `apply`.
- A chain-walking error reporter (anyhow/eyre style, printing each `source()`'s `Display`) can still show the token-endpoint body; `Display` and `Debug` of the top-level error do not (`redacted_token_errors_keep_the_body_out_of_debug`).
- A credential header value that is not UTF-8 fails the call with `remoteagent: apply auth credential: header "<name>" has a value that is not valid UTF-8` (a2a-rs `ServiceParams` values are strings); Go sends the bytes (`interceptor_refuses_a_credential_header_that_is_not_utf8`).
- `new_a2a` with `auth` fails with `remoteagent: build the A2A HTTP client: <reqwest error>` when reqwest cannot initialize its TLS backend (Go's `http.Client` literal cannot fail). `new_agent_card_provider` and `new_a2a_client_provider` return no error, so their default clients panic on that same failure, as reqwest's `Client::new` does.
- The credential provider gets `AuthContext { identity }`, never the invocation context (the scope via `current_credential_scope()`); there is no typed-nil `Auth` check.
- The a2a-rs JSON-RPC client ignores the HTTP status: a 401 surfaces as `failed to parse JSON-RPC response: …`, and a refused redirect as reqwest's `error following redirect for url (<url>)` (the policy's `remoteagent: refusing redirect …` text is lost).
- `ErrUnsupportedCardSource` / `ErrUntrustedCardInterface` are not distinct error kinds; the texts are identical and are matched by prefix.
- A bracketed non-IP card host reports `invalid host: ParseAddr("<h>"): unable to parse IP` instead of netip's specific reason.
- HTTP and JSON error details in card fetches are reqwest's and serde_json's, not Go's.
- `go_url::Url::to_go_string` (the card URL in error texts) writes the authority and the fragment as parsed; Go's `URL.String` re-escapes the host, userinfo and fragment (error text only).
- a2a-rs strips `http://` from GRPC interface URLs when decoding a card, so a loopback-http GRPC interface fails the origin check (Go accepts it).
- A transport-creation failure other than "no compatible transport" surfaces a2a-rs's last error, not Go's joined `failed to open a connection: …` (unreachable with the default factory).

a2a-rs wire differences (wire replay deltas, `crates/gadk-a2a/testdata/wire/*.deltas.json`):
- a2a-rs's task store keeps only a `Task` event's own metadata and does not move the previous status message into `history`, so `SendMessage`/`GetTask`/`CancelTask` task results lack Go's merged status-update metadata (`adk_app_name`, `adk_session_id`, `adk_user_id`, `adk_transfer_to_agent`, the ADK extension key) and the earlier status messages in `history` (also `test_a2_a_task_carries_adk_extension_meta`, `test_a2_a_input_required`).
- a2a-rs backfills `status.timestamp` on every task and status event, so the streamed submitted task carries a timestamp (Go: none).
- a2a-rs encodes A2A metadata through protobuf `Struct`, so metadata integers go on the wire as floats (`5.0`; Go `5`); gadk-a2a decodes metadata through Go's JSON text, so integral floats still fill integer fields (`integral_floats_decode_into_integer_fields`).
- a2a-rs's SSE responses set only `Content-Type: text/event-stream` and `Cache-Control: no-cache` (Go also sends `Connection: keep-alive` and `X-Accel-Buffering: no`).
- a2a-rs's REST binding answers JSON with `Content-Type: application/a2a+json` (a2a-go: `application/json`).
- a2a-rs's agent-card endpoint adds `Cache-Control: max-age=300` and an `ETag`.
- a2a-rs's client sends reqwest's `Accept: */*` on non-streaming JSON-RPC and REST calls and on the agent-card fetch (a2a-go: no `Accept` for JSON-RPC, `application/json` for REST).
- a2a-rs has no executor cleanup hook (Go's `a2asrv` cleanup interface); tests stand in with the end of the execute/cancel stream.
