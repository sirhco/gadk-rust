# Parity ledger — sub-project 5a

ADK-Go commit: see `docs/parity/ADK_GO_COMMIT`. Test-name rule: see the 1b spec § Parity tooling.

Rows below the table header are generated by `python3 scripts/parity-check --ledger 5a --generate`
from annotations in each Go test file's Rust target. Do not edit rows by hand:
- `fn test_foo` in the target → `ported`; a `// parity: adapted: <reason>` line within the 3
  lines above the `fn` → `ported (adapted: <reason>)`;
- a line `// parity: skipped TestFoo: <reason>` in the target → `skipped`.

Targets follow `target_name` (`server/adkrest/controllers/sessions_test.go` →
`server_adkrest_controllers_sessions.rs`): tests of Go-internal code (the wire DTOs, the origin
guard, the route table, the agent-graph writer, the debug store, the OIDC validator seam,
`internal/compactionvalidate`, `internal/telemetry`) live in `crates/<crate>/src/parity_tests/`;
tests of public API in `crates/gadk-server/tests/`; `functionaltest/telemetry_schema_test.go` is the
test directory `crates/gadk-engine/tests/internal_telemetry_functionaltest_telemetry_schema/` with
Go's `testdata/` goldens. `agent/loader_test.go` keeps its row in `docs/parity/1b.md`.
Go-deprecated APIs (`controllers.NewRuntimeAPIController`, `RuntimeAPIController.WithAuthorizer`,
`controllers.Unimplemented`, `triggers.NewPubSubController`, `triggers.NewEventarcController`)
are not ported; a Go test that exists only for one is skipped with that reason.

Accepted divergences (each annotated where it lives):
- a handler panic answers 500; Go's `net/http` logs the panic and aborts the connection;
- `Date`, `Content-Length` and `Transfer-Encoding` framing is hyper's;
- `/version` values are gadk's;
- `MultiLoader::list_agents` and its not-found error list agents in registration order (root
  first); Go uses map order (unspecified);
- debug spans come from `tracing`; trace and span IDs are generated by the debug layer rather than
  an OTel SDK, and OTel log records are `tracing` events;
- Google ID token verification is gadk's own (jsonwebtoken and cached JWK sets); causes differ
  from `idtoken`'s but are never sent to clients. It is stricter than `idtoken` in two fail-closed
  ways: a payload repeating a standard claim is rejected (Go: the last one wins), and an ES256
  signature must be exactly 64 bytes (Go accepts a longer `s`);
- request bodies decode with exact JSON key names (Go's `encoding/json` also matches keys
  case-insensitively), and `RunAgentRequest`'s required-field check reports the first missing
  field in the order `appName`, `userId`, `sessionId`, `newMessage` (Go iterates a map);
- a missing session reads `session not found: "<id>"` (`…, cannot apply event` on append) in
  every handler, which is Go's in-memory service's phrasing, whatever the session backend;
- JSON syntax and type errors in request bodies keep serde's text after Go's prefix (Go's
  `encoding/json` words them differently; `unexpected EOF`, `EOF` and `json: unknown field "<name>"`
  are Go's); unknown fields nested inside `newMessage` are not rejected (Go's
  `DisallowUnknownFields` also applies to nested structs);
- a server without an agent loader answers `/run`, `/run_sse` and `/run_live` with 500
  `failed to load agent: no agent loader` and the event graph with 500 `no agent loader`; Go
  dereferences the nil loader and panics;
- a query pair with an invalid `%` escape is decoded leniently (Go's `url.ParseQuery` drops it);
- triggers: Eventarc `max_concurrent_runs <= 0` means unlimited (Go blocks or panics); trigger
  bodies are limited by axum's body limit (Go: `MaxBytesMiddleware`); decode-error texts after
  Go's prefixes are serde's, except `EOF` and `unexpected end of JSON input`;
- `/run_live`: on a client close frame tungstenite echoes the code and reason (gorilla echoes the
  code with an empty reason); close handling recognises tungstenite 0.29.0's error texts (the
  read limit from `Space limit exceeded`, a write after the close frame from `SendAfterClosing` /
  `AlreadyClosed`); per-read and per-write tokio timeouts stand in for socket deadlines; the live
  slot is released just before the socket drops (Go: after);
- `/run_live`'s WebSocket upgrade uses axum's extractor, which reads only the first `Upgrade` and
  `Sec-WebSocket-Version` header value: comma-listed or repeated values that gorilla accepts get
  500;
- the debug store represents Go's unmarshalable log bodies and attributes (e.g. NaN) as non-JSON
  text; gadk's log emitter never produces them;
- a tool-call part whose arguments were never set records `"arguments":null` in the telemetry
  message attributes (Go omits the key; real runs always set the arguments);
- structured span attributes (finish reasons, input and output messages, system instructions,
  tool-call arguments and results) are recorded as JSON-text bytes, which gadk's layers read as
  JSON; stock `tracing` subscribers render them as hex (sub-project 7 revisits this for
  exporters);
- `header` and `identity_aware_proxy` authentication read the user ID (and IAP email) header, and
  the router decodes path variables, with `from_utf8_lossy` (Go keeps the raw bytes): distinct
  non-UTF-8 identities or path values that differ only in their invalid bytes collapse to the
  same U+FFFD text, which matters to an authorizer that compares them strictly;
- workflow scope (`gen_ai.workflow.nested`, and whether an invocation gets its own
  `invoke_workflow` span) is read from the subscriber's span registry: it is seen only under a
  `tracing_subscriber::Registry`-based subscriber (Go: a context value);
- telemetry tool payloads (tool-call arguments and results) treat an empty map as Go's nil map:
  `null` in the legacy schema and the message attributes, and no content-capture arguments
  attribute, where Go records `{}` for an empty non-nil map;
- a HEAD response always carries the would-be `Content-Length` unless the handler set one (Go's
  `net/http` omits it for an empty body or one over its 2048-byte buffer); a HEAD request whose
  target does not decode gets the 400 without its `400 Bad Request` body (hyper drops HEAD
  bodies; Go writes the raw answer whatever the method);
- `/run_live` with the keepalive off: a client close whose reply times out waiting for a blocked
  writer still marks the close as sent, so that writer's later error is taken for gorilla's
  `ErrCloseSent` and its `WebSocket write error` log line is not written (gorilla's
  `WriteControl` timeout leaves `writeErr` unset);
- the Pub/Sub trigger, and the Eventarc trigger in structured mode, read the whole body (under the
  body limit) before decoding its first JSON value; Go's `json.Decoder` stops reading after it,
  so a valid envelope followed by enough trailing bytes to pass the limit is rejected here.
