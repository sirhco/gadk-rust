Scope: ADK-Go's `telemetry` package (`telemetry/telemetry_test.go`) and the OpenTelemetry contrib
GCP resource detector `go.opentelemetry.io/contrib/detectors/gcp` v1.47.0 (the version ADK-Go's
`go.mod` pins), both ported to `crates/gadk-telemetry`. The detector's test files are ledgered as
`contrib/detectors/gcp/<path>_test.go`; `scripts/parity-check` reads them from the module
(`$GCP_DETECTOR_DIR`, else `$(go env GOMODCACHE)/go.opentelemetry.io/contrib/detectors/gcp@v1.47.0`)
and their targets are `crates/gadk-telemetry/src/parity_tests/contrib_detectors_gcp_<path>.rs`
(the hyphen of `cloud-function` and `cloud-run` kept). `internal/utils_test.go` holds helpers
only. The launcher's telemetry tests (`cmd/launcher/internal/telemetry`, `cmd/launcher/web`)
are ledger 6's rows. gadk-telemetry's bridge layer (gadk's D6 `tracing` spans and log records
into the OpenTelemetry SDK) has no Go counterpart; its tests, the shared-ID test with the debug
layer (`tests/shared_ids.rs`) and the telemetry schema goldens through the exporter
(`tests/schema_goldens.rs`) have no rows.

Out of scope (not ported):
- the deprecated top-level detectors (`cloud-function.go`, `cloud-run.go`, `gce.go`, `gke.go`):
  ADK uses only `gcp.NewDetector()`; their tests are skipped with that reason;
- the contrib module's `Version()` and the `print`-tagged manual detector check;
- OpenTelemetry metrics and a Cloud Logging exporter (Go has neither: adk-go #479);
- OpenTelemetry context propagation (no ADK-Go package uses it).

Accepted divergences (each annotated `// Divergence (ledger 7a)` where it lives, unless noted):

Bridge (`bridge.rs`):
- Structured span attributes (Go SLICE and MAP: finish reasons, messages, system instructions, tool-call arguments and results) are exported as JSON-text string attributes; Go exports OTLP arrays and key-value lists (otlptrace v1.47.0 `tracetransform/attribute.go:90-105`). OpenTelemetry Rust span attributes cannot hold maps.
- Byte attributes (Go BYTESLICE) are exported as their standard base64 text; a `u64` above `i64::MAX` as its decimal text.
- Log-record values follow Go's `toLogValue` rules except that a JSON `null` is dropped (no empty `AnyValue`) and a `null` body leaves the record without a body.
- The instrumentation scope (`gcp.vertex.agent`, the crate version) carries no schema URL (Go's follows `ADK_TELEMETRY_SCHEMA_VERSION_OPT_IN`).
- No `exception` span event is recorded for an error status (Go `span.RecordError`): gadk's D6 spans carry the error message but no error type (not annotated: nothing to emit).
- A start attribute recorded again with a different value is exported twice (no emitter does this today).

Providers and setup (`providers.rs`, `setup.rs`, `http_client.rs`, `resource.rs`, `credentials.rs`):
- No global logger provider is set (OpenTelemetry Rust has none); `set_global_otel_providers` sets only the global tracer provider.
- `OTEL_EXPORTER_OTLP_*` variables other than the endpoints (headers, timeout, compression, protocol) are parsed by opentelemetry-otlp from the process environment, not the injected one, and by its rules: an unparsable endpoint fails `new` with `failed to configure exporters: failed to create OTLP HTTP exporter: <opentelemetry-otlp error>` (Go drops it and uses the default endpoint); `OTEL_EXPORTER_OTLP_TIMEOUT` bounds opentelemetry-otlp's retry deadline only, each request has Go's 10 s timeout.
- The GCP span exporter also sends `OTEL_EXPORTER_OTLP_HEADERS` (Go's `WithHeaders` replaces the environment's headers); `x-goog-user-project` is still sent exactly once.
- Exports run on the Tokio runtime that called `new` (`RuntimeHttpClient`): the batch processors' own threads hand each request to that runtime, so the providers must be created inside a runtime (`no Tokio runtime: telemetry exporters must be created from within one`, inside Go's exporter error texts) and shut down (`Providers::shutdown`, async) before it ends; a synchronous SDK `force_flush` on a current-thread runtime would wait on itself.
- The `telemetry.sdk.*` resource attributes are opentelemetry_sdk's: `telemetry.sdk.language` `rust` and `telemetry.sdk.version` `0.33.1` (Go: `go` and `1.47.0`, otel sdk v1.47.0 `resource/builtin.go`).
- A GCP quota project that is not a valid HTTP header value fails `new` (`failed to configure exporters: failed to create GCP span exporter: failed to parse header value`); Go's `otlptracehttp.WithHeaders` accepts any string and `net/http` rejects the request at export time (`invalid header field value`).
- `service.name` falls back to the SDK's `unknown_service` when the executable name is unknown (Go: `unknown_service:go`).
- ADC: the file read and parse error details inside Go's wrapping texts are Rust's I/O, serde_json and google-cloud-auth texts; without `HOME` in the injected environment there is no well-known file (Go falls back to `user.Current()`).
- Shutdown errors are opentelemetry_sdk's provider errors (`Operation failed: Shutdown errors: [InternalFailure("<processor error>")]`), joined with `\n` as Go's `errors.Join`.

GCP detector (`gcp_detector/`):
- With an injected metadata base URL `on_gce` probes only that URL (no DNS race with `metadata.google.internal.`); on Windows the system-information hint is `false` (Go reads the registry's `SystemProductName`).
- `OnGCE` and the project ID are not cached process-wide (compute/metadata v0.10.0 `metadata.go:35-39,96-101` caches them); each detector asks again.
- The innermost transport and JSON-syntax error texts inside Go's wrapping texts are reqwest's and serde_json's; of `machineType` keys differing only in case the last in sorted key order wins (Go: the last in the document).
- A failing `compute instances.get` status is rendered with the code's canonical reason (`499 ` for a code without one); Go's `res.Status` carries the server's reason phrase (contrib `internal/gke.go:115`).
- Go's failing test transport (`Err: fake error`) is ported as a fake server answering `403 fake error`, which is not retried (test adaptation; not annotated).

Launcher (`gadk-launcher/src/telemetry.rs`; ledger 6 lists the launcher's own):
- An existing global `tracing` subscriber is kept and logged (Go always replaces the global OpenTelemetry providers).
