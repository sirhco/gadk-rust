Accepted divergences (each annotated `// Divergence (ledger 7b-1)` where it lives; 20):

Configuration and schema:
- `GCSUploadTimeout` (and every Go `time.Duration`) is a `std::time::Duration`, which cannot be negative: `apply_defaults` replaces only a zero `gcs_upload_timeout` (Go: `<= 0`), and negative `BatchFlushIntv` / `ShutdownTimeout` values Go keeps are unrepresentable (`tests/support/golden_apply_defaults.rs` pins the probe's `negatives` case) — `crates/gadk-agentanalytics/src/config.rs` (`apply_defaults`).
- `SerializedArrowSchema` bytes: arrow-rs encodes the same schema with a different flatbuffer layout (events schema 1864 bytes vs arrow-go's 1880; both one continuation-framed schema message plus the end-of-stream marker); BigQuery Storage Write decodes either, and the tests compare decoded schemas and pin both lengths — `crates/gadk-agentanalytics/src/schema.rs` (`serialize_arrow_schema`).

BigQuery REST client:
- Job IDs come from a v4 UUID (hyphens removed): Go's shape `^[0-9a-f]{32}$`, but 122 random bits instead of `crypto/rand`'s 128 — `crates/gadk-agentanalytics/src/gax.rs` (`random_id`; moved there from `bigquery/rest.rs` in 7b-2, shared with the GCS offloader).
- A `jobs.insert` reply without `jobReference` keeps the reference that was sent (Go's `bqToJob` dereferences nil and panics) — `crates/gadk-agentanalytics/src/bigquery/rest.rs` (`insert_query_job`).
- A `null` entry in a job's `status.errors` is skipped (Go appends a nil `*bigquery.Error`) — `crates/gadk-agentanalytics/src/bigquery/rest.rs` (`job_status`).
- An error reply's `error.code` outside `u16` (negative or above 65535) keeps the HTTP status (Go's `googleapi.Error.Code` is an `int` and keeps the body's value) — `crates/gadk-model/src/rest/googleapi.rs` (`api_error_from_response`; moved there from `bigquery/rest.rs` in 7b-2).
- An empty `TableMetadata::schema` counts as no schema (Go tests `Schema != nil`: a non-nil empty schema is sent as `"schema":{}` and rejected beside a view query) — `crates/gadk-agentanalytics/src/bigquery/rest.rs` (`table_resource`).
- A table reply's `timePartitioning.expirationMs` (Go: an `int64` with the `,string` tag): a bare JSON number is accepted (a non-`u64` one as 0) where Go fails to decode, and a negative string is a parse error where Go yields a negative expiration (a `Duration` cannot be negative); BigQuery sends a non-negative string — `crates/gadk-agentanalytics/src/bigquery/rest.rs` (`table_metadata_from_reply`).
- Go's `retryableError` also retries the exact texts `http2: stream closed` and `http2: client connection lost` (Go net/http's HTTP/2 errors); the gadk transport's HTTP/2 failures have other texts and retry only as a refused or reset connection or a timeout — `crates/gadk-agentanalytics/src/bigquery/rest.rs` (`retryable_error`).

Redaction:
- A percent escape that decodes to invalid UTF-8 inside a URI component that gets redacted is re-escaped from U+FFFD (`%EF%BF%BD`) where Go writes the original byte (`%FF`) back — `crates/gadk-agentanalytics/src/redaction.rs` (`lossy`).
- Byte offsets Go may cut inside a rune (`s[:maxInspectableJSONTextBytes]`, `loc[0]+1`) are rounded to a char boundary (a Rust `&str` cannot hold the partial rune); no probe corpus input reaches them — `crates/gadk-agentanalytics/src/redaction.rs` (`floor_boundary`, `ceil_boundary`).
- `applyContentFormatter`'s `%T`: a formatter error is written as `error` (Go: its dynamic type, e.g. `*errors.errorString`), a panic value as `string` for `&str` / `String` payloads, else `unknown` — Rust has no runtime type name for a `Box<dyn Error>` or a panic payload — `crates/gadk-agentanalytics/src/redaction.rs` (`FORMATTER_ERROR_TYPE`, `panic_type_name`).
- A panicking content formatter is still reported by Rust's panic hook (stderr by default) before `catch_unwind` returns; Go's `recover` is silent. The result and the logger line are Go's. The panic message often carries payload data (`panic!("bad {v}")`, an `expect` on an `Err` holding the value), so it reaches stderr or any installed hook (Sentry, tracing-panic) unredacted, outside the fail-closed path; and under `panic = "abort"` nothing is caught and the process aborts. Swapping the global hook around the call would race other threads, so the code stays; the `ContentFormatter` doc tells formatters to return `Err` instead of panicking — `crates/gadk-agentanalytics/src/redaction.rs` (`apply_content_formatter`).

Formatter (`SmartTruncate` over serde):
- A type with a Go `MarshalJSON` (e.g. `time.Time`, chrono in gadk) costs one node of the sanitize budget; Go takes a node for the value and another for the decoded method result, so the outputs differ only when the node budget runs out on exactly that value — `crates/gadk-agentanalytics/src/formatter/sanitize.rs` (module doc).
- A Rust `char` (Go has none; a rune is an `int32`) is sanitized as a one-character string — `crates/gadk-agentanalytics/src/formatter/sanitize.rs` (`serialize_char`).
- Enum variants with data (newtype, tuple, struct; no Go value) are sanitized in serde_json's `{"variant": …}` form — `crates/gadk-agentanalytics/src/formatter/sanitize.rs` (`serialize_newtype_variant`).
- A `RawValue` (Go `json.RawMessage`) nested deeper than 100 levels is `[UNSUPPORTED_OBJECT]` (decoded by the port of Go's `decodeJSONValue`, which stops there); Go decodes it with `json.Decoder` (10000 levels) and the walk writes `[MAX_DEPTH_EXCEEDED]` — `crates/gadk-agentanalytics/src/formatter/sanitize.rs` (`finish_raw`).
- An integer outside `i64` / `u64` (an `i128` / `u128`, or such a `json.Number`) loses its low digits in the sanitized `Value` form: serde_json without `arbitrary_precision` holds it as the nearest `f64`, where Go keeps the `json.Number` text; the JSON-text form (`smart_truncate`) writes the digits unchanged — `crates/gadk-agentanalytics/src/formatter/sanitize.rs` (`San::into_value`).
- No cycle detection: a `Serialize` value cannot contain itself, so `[CIRCULAR_REFERENCE]` is never written (Go tracks visited maps, slices and pointers) — `crates/gadk-agentanalytics/src/formatter.rs` (`CIRCULAR_REF_PLACEHOLDER`).
- A queued inline-data upload shares the caller's immutable `Bytes` buffer instead of Go's `bytes.Clone` copy (nothing can change the bytes through the message, so the queued data is the same) — `crates/gadk-agentanalytics/src/formatter/parts.rs` (`add_inline_data`).

Not annotated (no Go-observable effect, or not applicable):
- `Config` is not `Deserialize` (spec R1): `TestConfig_CreateViews`' `json.Unmarshal` subcase is struct construction (adapted row). Go `[]option.ClientOption` is `ClientOptions { credentials, without_authentication, http_client, endpoint, headers }`; Go `context.Context` is the crate's `Context`; `%w` chains are `Error::Wrapped` / `Error::Joined`.
- Go nil vs empty slices and maps (`DefaultConfig().CustomTags` is `{}`, a zero config's `nil`) are both empty `Vec` / `Map`; no in-scope code tells them apart (the config golden writes both as `null`).
- Go ranges over `map[string]any` in random order; the redaction walk visits keys sorted. Outputs differ only when the node budget runs out inside a multi-key map, where Go itself is nondeterministic.
- RE2 sources are Go's, translated mechanically (`\s`, `\w`, `\b` to their ASCII forms); Go `unicode.IsLetter` / `IsDigit` are `\p{L}` / `\p{Nd}` regex classes, whose Unicode version is the `regex` crate's (it may differ from Go's for newly assigned code points).
- `TestSanitizeRawText`'s linear-time subtest divides its input sizes by 16 in debug builds (Go: 4, or 64 under `-race`, via `race_test.go` / `norace_test.go`'s `raceEnabled`) and keeps Go's 3 s limit.
- `smart_truncate` takes `T: Serialize`, so Go's reflection over unexported fields, struct embedding and `omitempty` shadowing are adapted in the `TestWalkStruct_*` rows over serde types producing the same JSON.
- REST request headers: gadk sends its own `User-Agent` and no `x-goog-api-client` (spec R9 excludes both from the comparison); the `Accept-Encoding` / `Content-Length` Go's transport adds are transport artifacts.
- N/A: Go's gRPC-status branches of `hasErrorCode` and the `codes.Canceled` check are kept (`Error::Status`) for 7b-2's gRPC errors; no 7b-1 path produces a status error.
